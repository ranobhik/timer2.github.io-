# «Рабочая партия» — аниме-портал

Статический сайт для просмотра аниме с админ-панелью. Без сервера, базы данных и сборки: чистые HTML/CSS/JS, которые GitHub Pages отдаёт как есть.

- 🎠 Карусель релизов на главной: автопрокрутка, стрелки, точки, свайп
- 🖼 Постеры подтягиваются с Shikimori по ID — без запросов к API и без CORS
- 🌙 Тёмная тема по умолчанию + светлая, переключатель в шапке
- 📱 Полная адаптивность: от 320 px до широких мониторов, ничего не обрезается
- 🛠 Админ-панель: аниме, эпизоды, плееры кодом, жанры, тексты, цвета, меню, CSS
- 🎬 Плееры: iframe-ссылка, готовый код вставки (embed), `.mp4` / `.m3u8`
- ⭐ Избранное и «Продолжить просмотр» (локально в браузере)
- 🔍 Каталог с поиском, фильтрами по жанру/году/статусу и сортировкой

---

## Быстрый старт

Сайт не требует сборки. Достаточно открыть его через любой статический сервер:

```bash
# из корня репозитория
python3 -m http.server 8000
```

Затем откройте <http://localhost:8000>.

> Через `file://` каталог не загрузится (браузер блокирует `fetch`), поэтому нужен именно сервер — локальный или GitHub Pages.

## Публикация на GitHub Pages

1. Запушьте репозиторий в GitHub (ветка `main`).
2. `Settings → Pages → Build and deployment → Source: GitHub Actions`.
3. Workflow `.github/workflows/deploy.yml` сам выложит `index.html`, `assets/` и `data/`.
4. Сайт будет доступен по адресу `https://<логин>.github.io/<репозиторий>/`.

Сайт использует только относительные пути и hash-маршруты (`#/anime/...`), поэтому
одинаково работает и в корне домена, и в подкаталоге.

## Админ-панель

Адрес: `#/admin` (или кнопка «Админ» в шапке).

**Пароль по умолчанию: `rabpartiya`** — смените его в разделе «Публикация и доступ».

Разделы:

| Раздел | Что можно делать |
| --- | --- |
| **Контент** | Список аниме, публикация, флажок «на главной», дублирование, удаление |
| **Редактор аниме** | Название, постер, баннер, Shikimori ID, описание, жанры, рейтинг, эпизоды и плееры |
| **Жанры** | Добавление, переименование (обновляет карточки), удаление |
| **Настройки сайта** | Название, подпись, описание, логотип, цвета, тема, объявление, соцсети, меню, свой CSS |
| **Публикация** | Экспорт/импорт JSON, отмена локальных правок, смена пароля |

### Как добавить аниме

1. `#/admin/content` → **«Добавить аниме»**.
2. Заполните название, год, жанры и описание.
3. Постер: вставьте ссылку на картинку **или** загрузите файл (до 900 КБ).
4. Добавьте эпизод кнопкой **«Эпизод»**, внутри эпизода — плееры кнопкой **«Добавить плеер»**.
5. **«Сохранить»** — запись появится в каталоге.

### Постеры с Shikimori

У каждого аниме есть поле **Shikimori ID** (например, `16498` — «Атака титанов»).

- Если постера нет, сайт сам подставляет картинку по адресу
  `https://shikimori.one/system/animes/original/<ID>.jpg`. Это обычный `<img>`, поэтому
  работает без API, без CORS и без задержек; при ошибке показывается аккуратный
  градиентный постер с инициалами.
- В админке кнопка **«С Shikimori»** у поля постера (и кнопка ⬇ в списке контента)
  обращается к официальному API: подтягивает постер, год, рейтинг, жанры и описание
  (API отдаёт `Access-Control-Allow-Origin: *`, поэтому работает прямо из браузера).
  Если сети нет, постер всё равно подставляется по ID.
- Кнопка **«Постеры»** в разделе «Контент» проходит по всем аниме без картинки.
- Найденные постеры кешируются в `localStorage` на 30 дней.

> ID можно узнать в адресной строке Shikimori: `shikimori.one/animes/16498-...` → `16498`.

### Как подключить плеер через код

У каждого плеера есть тип:

- **Iframe по ссылке** — вставьте URL страницы плеера, сайт создаст `<iframe>` сам.
- **Код вставки (embed)** — вставьте готовый HTML от плеера, включая `<script>`:

  ```html
  <iframe src="https://kodik.info/serial/12345/abcdef/720p"
          allowfullscreen allow="autoplay; fullscreen"></iframe>
  ```

- **Видеофайл** — прямая ссылка на `.mp4` или `.m3u8` (HLS подхватывается автоматически через hls.js).
- **Заглушка** — на сайте будет аккуратная плашка «Плеер ещё не подключён».

У эпизода может быть несколько плееров — это удобно для разных озвучек. Зритель
переключает их в панели под плеером.

> ⚠️ Код вставки исполняется в браузере посетителя. Подключайте только те плееры,
> которым доверяете, и только легальный контент.

### Как изменения попадут на сайт для всех

GitHub Pages — статический хостинг, поэтому админка сохраняет правки в
`localStorage` вашего браузера (черновик). Чтобы обновить сайт для всех:

1. `#/admin/publish` → **«Скачать catalog.json»** (или «Скопировать»).
2. В GitHub откройте `data/catalog.json` → карандаш → вставьте новый JSON → Commit.
3. GitHub Actions пересоберёт сайт за минуту.

Или из терминала:

```bash
cp ~/Downloads/catalog.json data/catalog.json
git add data/catalog.json
git commit -m "Обновление каталога"
git push
```

**«Отменить локальные правки»** удаляет черновик и возвращает данные из `data/catalog.json`.

## Структура проекта

```
index.html               разметка шапки, подвала, мобильной навигации
assets/css/style.css     дизайн-система, темы, адаптивность
assets/js/app.js         роутер и страницы (главная, каталог, аниме, просмотр…)
assets/js/admin.js       админ-панель
assets/js/store.js       каталог, черновик, настройки, избранное, пароль
assets/js/ui.js          карточки, постеры, плееры, тосты
assets/js/shikimori.js   автопостеры по ID и обогащение данных через API

legacy-timer/            старый проект «Таймер ET-66» (React + Vite), больше не деплоится
```

## Адаптивность и дизайн

- Сетки на `auto-fill / minmax` и `clamp()` — карточки не ломаются на узких экранах.
- Иконки — инлайн-SVG с фиксированными размерами, поэтому элементы не «раздуваются».
- Главный экран — карусель с адаптивной высотой, на телефонах постер скрывается,
  а фоном становится размытая обложка.
- Плеер держит пропорцию `16:9` и не выходит за высоту экрана.
- На мобильных: нижняя навигация, безопасные отступы (`env(safe-area-inset-*)`), таблицы админки скроллятся по горизонтали.
- Поддержка `prefers-reduced-motion` и режима повышенной контрастности системы.
- Акцентные цвета и тема меняются в админке, без пересборки.

## Ограничения статического хостинга

- Пароль админки — локальная защита интерфейса, а не серверная авторизация. Не используйте важные пароли.
- Загруженные в админке картинки хранятся в `localStorage` (лимит ~5 МБ). Для десятков постеров используйте ссылки или закоммитьте файлы в `assets/img/`.
- Правки видны всем только после публикации `data/catalog.json` (см. выше).
- Сайт не хранит видео: он лишь встраивает плееры, которые вы указали.
